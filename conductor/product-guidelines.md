# Product Guidelines

## Workflow

- Keep the lifecycle minimal and approval gates explicit.
- Keep canonical doctrine in `skill/SKILL.md`; compatibility wrappers must
  not introduce competing methodology.
- Preserve existing project conventions and user changes.

## Communication and Evidence

- Use concise instructions, clear file paths, and actionable verification steps.
- Distinguish verified results, assumptions, and checks that were not performed.
- Do not claim completion based on tests that were not run.

## Integrations

- Keep optional integrations replaceable.
- Document proposed capabilities in tracks rather than describing them as
  existing behavior before implementation and review.
